采样、温度与 KV Cache
本课目标　采样控制如何选 token；KV Cache 复用前缀计算；推理优化主要改善效率。

01 / 从 logits 到概率

Logits 是词表中各 token 的未归一化分数。Softmax 把这些分数变成总和为 1 的概率。模型计算概率之后，还需要一条规则决定输出哪个 token。

贪心解码每次选最高分候选；随机采样按分布选择。Top-k 保留分数最高的 k 个候选；top-p 保留累计概率达到阈值的最小高概率候选集合，再归一化采样。

02 / 温度会怎样改变选择

温度 T 通常通过 softmax(logits / T) 调整分布。正温度较低时，概率更集中；较高时，更平坦。界面中的温度 0 通常用确定性的贪心选择来处理，不直接除以零。

高温度不等于更有创造力，低温度也不保证事实正确。它改变的是候选选择分布，并不为答案增加证据。

03 / KV Cache 为什么能加速

生成下一个 token 时，已有前缀在因果模型里的表示不会因新增未来 token 而改变。因此可以保存各层历史 token 的 K、V，让新 token 的 Q 直接与缓存的 K、V 计算注意力，减少重复计算。

KV Cache 用更多显存换取较少的重复工作。上下文越长、同时处理的序列越多，缓存通常越大。它不是检索知识库，也不是长期记忆，更不是训练参数。

04 / 理解速度的两个阶段

Prefill 先处理输入提示，并建立缓存；Decode 随后逐步生成输出。长输入会增加首个 token 出现前的等待，长输出会拉长持续生成的时间。

Continuous Batching 在请求完成或新请求到达时动态调整批次；PagedAttention 改善 KV 缓存的内存管理。它们解决服务效率问题，不直接改变模型是否理解或回答正确。

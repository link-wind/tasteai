张量布局

Q/K 布局为 [B,H,T,d]，d为偶数，相邻维配对。positions[T] 保存逻辑位置，可从非零开始。

若各样本位置不同，应显式准备与 [B,1,T,1] 兼容的角度布局；广播不报错并不保证轴正确。

张量形状含义
x[B,H,T,d]待旋转的 Q 或 K
inv_freq[d/2]每个维度对的频率
angles[T,d/2]位置乘频率
even / odd[B,H,T,d/2]偶/奇坐标切片
输出[B,H,T,d]交错恢复原布局

输出必须恢复 [B,H,T,d]，不能停留在 [B,H,T,d/2,2]。

完整的相邻配对旋转

先形成角度与 cos/sin，再转为输入dtype参与旋转：

def rope(x, positions, base=10000.0):
    d = x.shape[-1]
    inv = base ** (-torch.arange(0, d, 2, dtype=torch.float64,
                                device=x.device) / d)
    angles = positions.to(device=x.device, dtype=torch.float64)[..., None] * inv
    cos, sin = angles.cos().to(x.dtype), angles.sin().to(x.dtype)
    even, odd = x[..., 0::2], x[..., 1::2]
    paired = torch.stack((even*cos - odd*sin,
                          even*sin + odd*cos), dim=-1)
    return paired.flatten(-2)

stack 使每对坐标相邻，flatten(-2) 恢复d维。直接cat两组会改变维度排列。

本课用float64角度方便核对；实际实现需权衡精度与吞吐。

独立参考实现

独立参考可把 (a,b) 视作复数a+ib，乘 exp(iφ) 完成同一旋转。

z = torch.view_as_complex(x.reshape(*x.shape[:-1], -1, 2).contiguous())
phase = torch.polar(torch.ones_like(angles), angles)
expected = torch.view_as_real(z * phase).flatten(-2)

对照时检查dtype与布局，并测试零位置、范数和相对内积。

非零位置、多维向量、多头和不同长度能暴露仅测位置0发现不了的错误。

增量解码与 offset

已有100个token时，下一项虽令T=1，逻辑位置仍应是 [100]，不能使用 arange(1) 的 [0]。

past_length = 100
new_length = 1
positions = torch.arange(past_length, past_length + new_length)
q_new = rope(q_new, positions)
k_new = rope(k_new, positions)
# 将已旋转的 k_new 追加到历史 K；不要把旧缓存再旋转一次

通常缓存已旋转的旧K，只旋转并追加新K；缓存裁剪后的物理长度也未必等于逻辑位置。

两种配对约定

相邻配对 (x₀,x₁)/(x₂,x₃) 与 split-half 配对 (x₀,x₂)/(x₁,x₃) 对同一输入一般产生不同结果。

布局可通过一致置换关联，但需同时对齐Q/K投影权重、频率与旋转函数。

测试不能只问“有没有报错”

不能只检查shape；还应比较非零位置数值、范数、点积与增量一致性。

接进注意力与缓存的验证顺序

先旋转Q/K再计算QKᵀ。GQA头数可不同，但头维度和旋转约定需匹配。

对同一输入比较：全序列用 [0,1,2,3,4]，增量逐项使用真实位置后拼接，结果应一致。

full = rope(x, torch.arange(5))
parts = [rope(x[:, :, i:i+1], torch.tensor([i])) for i in range(5)]
incremental = torch.cat(parts, dim=2)
assert torch.allclose(full, incremental)

这里只验证旋转层offset；完整缓存服务还需核对可见性、padding与写入逻辑。

交互实验

练习

自测与解析 · 6 题

先作答，再展开解析。

01 · 为什么 d 必须为偶数？

展开逐步解析

本课将全部旋转维度两两配成二维平面。若只旋转部分维度，也必须让这部分满足配对条件，其余维度按模型约定保留。

02 · stack 后为什么要 flatten 最后两维？

展开逐步解析

stack 得到每对的两个新坐标，末尾形状为 [d/2,2]。flatten(-2) 按配对顺序恢复 d 维，保持外部接口。

03 · 为什么位置 0 测试不足以发现配对错误？

展开逐步解析

此时所有平面都是恒等旋转，sin=0、cos=1。非零位置才能暴露错误的频率、符号和维度配对。

04 · 已经处理 100 个 token，下一次 T=1 应使用什么 positions？

展开逐步解析

在从 0 开始且未重映射的逻辑位置约定下，应为 [100]，而不是 arange(1) 得到的 [0]。

05 · 为什么不能每步对缓存中旧 K 再旋转？

展开逐步解析

旧 K 已带有位置旋转。再次旋转会叠加额外角度，让历史位置随步数漂移。通常只旋转新 K 后追加。

06 · 两种 rotate_half 都输出正确 shape，为什么还可能不兼容？

展开逐步解析

坐标配对不同会改变同一输入的数值与点积。需要对齐投影权重、布局与频率；shape 相同不是语义兼容证明。
